# Batched evaluator reuse and scientific review

Date: 2026-10-07. Independent source/API research and focused native probes. Production implementation acceptance is recorded separately below as the caller and kernel adapters become available. No dependency or numerical algorithm is changed by the research probes.

## Native owners and layouts

The pinned Symbolica revision is `58652fabc2f736302a570deaaf8d517679f7fe6e`, with SymJIT 2.26.4 and Numerica 3.0.1. Symbolica exposes `JITCompiledEvaluator<T>::batch_evaluate(args, out, rows)` for the existing `f64` and `Complex<f64>` evaluator types (`src/evaluate/backend.rs:945–954`, dispatch at 836 and 1306). These call SymJIT's existing matrix evaluator. Inputs are point-major rows in the evaluator's ordered input schema, including runtime parameters; outputs are point-major rows of the entire ordered Laurent vector. Complex entries remain native `Complex<f64>` until the FastSecDec presentation layout of adjacent real/imaginary scalar components is applied.

This route reuses the currently compiled O2 evaluator and exact IR. It does not require an explicit wide-vector input type, a new expression representation, or caller-written lane transposition. SymJIT `src/symjit/applet.rs:191–278` runs native SIMD groups when available and scalar tails for incomplete groups. Its branch/callback fallback remains native. Callers should supply only genuine rows: no synthetic zero coordinates or padded lanes should become evaluated sample diagnostics or enter estimators.

The existing FastSecDec `kernel/function_map_probe/rank_five.rs:388–404` already compares the same public scalar and matrix routes on complete actual-sector coefficient vectors. That historical benchmark is reuse evidence, not performance evidence for this new integration path.

The direct JIT matrix entry does not validate buffer dimensions before native writes. The `BatchEvaluator` trait wrappers only check divisibility, which is insufficient to prove evaluator dimensions, and their zero-row path is not a suitable public admission guard. FastSecDec must check multiplication overflow, exact input/output lengths and row count before calling the owner, return cleanly for zero rows, and support nonempty batches with zero input dimension without calling `chunks_exact(0)`. The focused probe safely exercises only correctly sized native buffers.

`ExpressionEvaluator<T>` exposes `evaluate` and fallible `try_evaluate` (`src/evaluate/evaluator.rs:249–270,361–363`), but no batch API in this pinned source. The native `BatchEvaluator` implementations cover compiled f64/complex f64/SIMD/CUDA evaluators, not eager `DoubleFloat`, `Float`, or portable eager f64. The bounded adapter for those backends must therefore iterate rows through the existing native evaluator, retaining its mapped coefficient/cache owner. This is batched caller input with scalar native fallback, not a claim of SIMD for 106-bit or 3322-bit arithmetic. No second interpreter or arithmetic implementation is needed.

SymJIT's default configuration enables SIMD and disables its internal Rayon threads. Its default constructor also reads `SYMJIT_TOML` or a local `symjit.toml`, so caller-owned parallelism should be enforced explicitly with Symbolica's public `JITCompilationSettings::with_option("use_threads", "false")`. The CLI's bounded worker pool remains the sole thread owner. Scalar/matrix numerical equivalence must be measured on scientific controls; host SIMD and native intrinsic choices do not justify a universal bitwise-equivalence promise.

## Sampling, weights and acceptance order

Numerica's public integration API has scalar `sample`, `add_training_sample`, statistics accumulation and explicit `update`; no public batch sampling or batch training operation was found. Reusing those operations in a bounded collection loop is the smallest adapter. `ContinuousGrid::sample` reads the existing partitions and probability floor (`numerical_integration.rs:1136–1163`); `DiscreteGrid::sample` reads the existing bin probabilities and native child sample (`916–939`). Training adds native accumulator data (`1187–1207`, `943–968`); adaptation changes the proposal only at explicit grid update (`1213`, `853`). Sampling a chunk ahead of its evaluations therefore preserves a frozen proposal within a native work package.

The adapter must retain RNG order, native sampled coordinates and root weights. Discrete evaluation may group points by sector to obtain useful evaluator batches, but it must preserve encounter order within each sector and restore the original global sample order before vector accumulation and native training. Each point receives its sampling weight exactly once, at its chosen numerical precision. The full Laurent vector stays together for cancellation and covariance; no separate coefficient sampling or independent real/imaginary estimator is admissible.

QMC must collect the existing transformed coordinates and Jacobian weights, preserving the original lattice/shift/package order and complete-package acceptance. Changing evaluator chunk length must not repartition scientific work packages or regroup floating sums. Existing proposal updates, complete shifts, completed native batches and convergence decisions remain at their existing boundaries.

Distance classification is per actual transformed point. Bulk f64 evaluation may precede ordered stability decisions, but it must not update maxima from tentative low-precision values. Weighted maximum tests see the same previous final finite per-sector maximum as the scalar path, excluding the current point. A rejected row escalates individually; cutoff zeros and failed points retain their distinct existing meanings. Completed lower-tier speculative work may be timed honestly without pretending it is a final-class outcome. No partial or failed batch may become an accepted estimator return or checkpoint record.

Evaluator chunk size is operational configuration. Its absence in an old caller snapshot can default to 256, and changing it on resume should be compatible with the same scientific task identities, RNG and point sequence. Scientific settings comparisons should exclude this operational field, while reports retain the actual chosen value. Required continuation controls compare full means, covariance, per-sector diagnostics and accepted task identities across scalar/odd/default chunk sizes; any real SIMD rounding difference should be bounded and explained rather than hidden through relaxed scientific admission.

## Timing semantics

One matrix call serves several points. Preserve separate counts of native evaluator invocations and actual evaluated rows; a batch's measured duration divided by its genuine rows is an amortized mean, not an individually timed sample latency. Input packing, sampling, stability decisions and output scattering belong to surrounding integrand/worker overhead. Native evaluator timing encloses only the actual native invocation (or each eager fallback invocation). Include real work on failed/discarded batches in operational timing, but never add padded or unevaluated rows. Historical snapshots were scalar-only, so missing matrix counters accurately default to zero. Total native invocations are `calls - matrix_points + matrix_invocations`; the original evaluated-point counts remain available.

## Implementation acceptance

The initial kernel source review accepts the bounded architecture. `WeightedEvaluationContext::evaluate_weighted_batch` validates public matrix shapes and finite input admission, selects primary f64 rows, appends bound runtime inputs, and uses the existing real/complex native matrix owner. The original scalar stability/replay logic receives those primary results in original row order. Higher precision retains its existing mapped evaluator/cache. The controlled form polls cancellation before matrix work and between ordered rows; the native call itself remains indivisible. A failed batch returns its completed report prefix and original `KernelError`; cumulative metrics retain all primary work, including speculative rows that must not be admitted scientifically.

`EvaluatorTiming.calls` retains its historical count of evaluated points. Additive `matrix_invocations` and `matrix_points` distinguish actual matrix dispatches; per-row nanosecond shares use quotient/remainder allocation so their sum equals the measured matrix span exactly. Native eager fallback continues to record individual owner calls. SymJIT internal threading is explicitly disabled through its public option, preserving caller-owned execution. Saved exact IR, evaluator settings and artifact policy are unchanged by the invocation adapter.

The initial worker source review also accepts ownership and order. Ordinary Havana retains genuine native samples, trains and accumulates in sample order, and returns only a complete task. Discrete Havana gathers each sector in encounter order, evaluates those groups, restores global RNG order, then uses the original training and complete-vector accumulators. QMC generates the same plan points and transforms them before the evaluator callback, then pushes outputs to the native partial in lattice order. A failed sector group can be encountered before another sector's earlier global row; because the whole task is rejected, this affects operational failure order rather than estimator admission. No result may describe such a group completion as a completed statistical package.

The independent runtime probe now passes against the rebuilt native release core. `output/batched-evaluation-review/runtime_batch_probe.rs` compares scalar evaluation with chunks 1, 7 and 256 over a 263-row complex family, a real family and a cold-loaded runtime-bound family. It exercises all distance classes, cutoff-only zeros, zero weights, maximum-driven f64-to-DoubleFloat-to-arbitrary escalation and the validated whole-vector replay policy. Every final class, checked/rescued/replayed flag and final replay state agrees exactly; full vectors agree within the declared scaled tolerance `2e-13`. Restoring replay state midway and continuing with a different chunk size preserves the same result/state. Matrix report durations, point counts and invocation counts sum exactly to cumulative metrics.

Invalid weights, invalid coordinates and a persistent nonfinite endpoint fail at the same row and with the same error as scalar evaluation. Their completed prefix vectors, reports and maxima match, and the failed numerical point is never converted to a cutoff zero. Invalid shapes and empty batches perform no evaluator work. A cutoff-only batch performs no evaluator work. Cancellation before the matrix performs none; cancellation after the matrix retained seven actual matrix points/one invocation but only two completed prefix state updates in the controlled probe. Artifact bytes remain unchanged. The final passing log is `output/batched-evaluation-review/runtime-batch.txt`.

The separate worker implementation probe was independently reviewed at `output/batched-evaluation/worker_probe.rs`, together with its passing `worker-probe.txt`. For chunk sizes 1, 7, 256, 513 and 1024, ordinary and discrete Havana preserve exact sampled-coordinate/weight bit traces, native pilot adaptation, production checkpoint scientific fields, full-vector covariance and live prefixes at point 257 and completion. QMC preserves those point/weight streams and covariance for None/Korobov2/Korobov3, including pending complete-shift previews and reverse return admission. Failed callbacks leave accepted checkpoints unchanged and restoration reissues the identical task for all three worker types. This author-run evidence supplements the independent native sampler and kernel probes; it is not described as another independent execution.

The kernel and worker milestone is accepted on these controls and source review. No overall speedup is inferred from noisy correctness runs performed concurrently with compilation. Matched performance and terminal interruption remain coordinating checks.

The portable adapter author also executed a fresh standalone portable-host probe; its source and passing log were independently inspected at `output/batched-evaluation-review/portable_batch_probe.rs` and `portable-batch.txt`. Real and complex rational families, runtime parameter values two and three, 263 rows and chunks 1/7/256 preserve scalar full vectors within `2e-13`, exact classification/replay flags and maxima, and genuine scalar evaluator call counts through f64/DoubleFloat/arbitrary/cutoff paths. Matrix counters correctly remain zero for eager fallback. Cold bytes remain unchanged and cutoff-only rows make no numerical calls. This is host portable execution, not actual Wasm; it introduces no Gamma-cost exception or unsupported SIMD claim.

## Final CLI and checkpoint review

The root-owned configuration slice is accepted on independent read-only review. `IntegrationInput` supplies default 256 when historical JSON/TOML omits `evaluation_batch_size`. Runtime overlays merge before explicit CLI flags, and `--evaluation-batch-size`/`--batch-size` share one `NonZeroUsize` parser. The effective settings reject an overlay value zero as well; the driver repeats this admission for direct callers. All three execution paths pass the chosen size through their batch adapters. The field does not alter statistical batch sizes, lattice packages, native sample counts or randomization.

The existing checkpoint settings normalization removes `evaluation_batch_size` alongside `workers` on both saved and current settings. Historical missing stability settings still explicitly retain the validated policy. Artifact content checks, the remaining scientific settings, replay identities and completed-task admission stay enforced. The artifact loader retains raw integration provenance rather than replacing it with deserialized defaults, so loading an older artifact does not rewrite its hash. Newly generated human provenance naturally records the current integration defaults under the existing artifact identity rules; numerical kernel/sector identities and saved exact evaluator bytes do not depend on evaluator chunk length.

The full chosen setting remains serialized into numerical result `caller_settings` through the existing provenance path. Read-only inspection of the coordinating configuration controls confirmed saved values 256 (default), 7 (overlay), and 3 (explicit alias overriding that overlay), while their checkpoint scientific settings omit the field. The README correctly identifies an operational chunk, describes native SIMD only for eligible f64 rows, retains eager/higher-precision owners and permits chunk changes on resume.

The coordinating old-binary/new-binary CLI evidence was independently inspected for QMC, discrete MC and ordinary MC with one/eight workers and chunks 1/7/256. These are coordinating executions with independently reviewed evidence, not duplicate executions by this reviewer.
