## Native ownership and reuse

`generation::RecipeFamilySession` advances the existing shared
`PreparedRecipeSet`/`PreparedChartSource` pipeline. Geometry and monomial-extracted
source records are shared; each recipe keeps its own exact symmetry proof,
formula context, deformed density and saved programs. The implementation does
not repeat `GenerationSession` once per recipe or accumulate completed
nonresident evaluator objects. Each sector is generated, compiled, appended
through the native `ProgramArchiveWriter` and released. Only the explicitly
requested resident recipe retains numerical owners.

The consuming `ResidentAssembly` is shared with selected-record restoration.
It owns Laurent/component remapping, native exact sums, checking-context
projection and helper lifetimes. Exact sums use the narrowly audited native
`expand_num` operation before pruning root associations. There is no second
CAS, graph/router, evaluator format, root solver, statistical accumulator or
generation-side copy of the loader's merge rules.

Dynamic differentiation still uses native Symbolica expressions and implicit
hooks, before native subtraction and jets. Runtime coefficient maps restore
saved native programs; policy remapping does not reconstruct expressions or
repeat Horner/CPE. The quadratic specialization uses native square root.
Higher-degree refinement uses the owner-prepared bracketed root API. Certified
checking uses native ball arithmetic and saved independent primitive/combiner
programs. The proof-specific radius inequalities do not implement another
general polynomial solver or evaluator.

Construction is inert. The caller supplies storage and advances bounded native
units, chooses pauses, owns durable publication, and receives frozen progress.
There is no library pool or background integration loop. The optional resident
recipe is independent of the archive default. Disk staging gives native
bounded-residency behavior; the existing Pyodide MEMFS probe does not establish
disk durability or a browser RSS bound.

## HEPKit and Python boundary

The new family bridge starts from the existing native `Integral` input and
parametrizes it once through the established HEPKit diagram/family/kinematics
owners. Its Rust wrapper delegates scheduling units and scientific work to
`RecipeFamilySession`; Python does not loop mathematical recipes itself.
`ContourSettings` mirrors the native enum and validated limits. The substantive
implementation stays in FastSecDec's isolated binding crate; Community needs
registration/reexports/stubs only.

The wrapper owns its temporary directory and file. Completed archives retain
that storage independently of the session. A resident selection returns the
existing native owner; other selections use the native indexed reader for only
that recipe. Returned kernels own their decoded metadata/programs independently
of archive storage. Repeated result access is retained. Raw archive export is
explicitly distinct from CLI manifest publication; imported raw archives do not
invent an artifact default.

Snapshots copy native values and their Python classes are frozen. Rendering,
inspection and session construction do not generate, contract or sample.
The earlier elapsed-time and resident-sector presentation corrections are
present. Python preflight clones a shared kernel owner before mutation, so an
existing integration session keeps its own mathematical prescription and pilot
state. QMC/Havana work and checkpoint ownership remain in their native owners.

The new family Python tests cover inert construction, pause/interrupt behavior,
monotonic active elapsed time, explicit resident/default selection, native
scientific parity, detached lifetime and save/reload. Their source is useful
coverage, **not an installed-host result**: the earlier private fixed wheel
predates the dynamic runtime and family bridge. A rebuilt coherent host and
regenerated stubs are required before claiming this new HEPKit path executed.

## Identity, checkpointing and validation

Physical-source identity, selected compiled-program identity and bound numerical
identity remain distinct. The versioned recipe and its saved programs enter
the selected identity. Ordered runtime inputs include the dynamic safety
fraction and both caps, and native binding hashes their exact f64 bit patterns.
Rebinding prepares every replacement owner and exact vector before committing;
failed rebinding preserves the previous usable problem.

Validation policy is absent from mathematical identity. Policy-only remapping
uses the same native saved programs and preserves valid pilot evidence; changing
physical parameters or caps creates a new binding epoch. Pilot plans and
receipts are scoped to that owner, exact point and a unique nonce. Sparse exact
root traces certify only native callbacks that actually executed, preserving
lazy branches and exact cancellations. Old checkpoint provenance is descriptive
evidence, not authority to unlock a new bound owner.

The ordinary CLI checkpoint strips `contour.validation` only. The serial wrapper
additionally permits operational residence/worker changes and delegates
statistical compatibility to the native serial session. Recipe, construction,
safety fraction and caps remain mathematical settings. Python QMC/Havana resume
builds the expected native integration problem and uses native restore/replay
admission. No contour callback consumes sampling RNG. CLI preflight uses a
separate native Numerica RNG and never submits pilot observations as production.

Checked numerical owners retain independent mutable scratch/counters.
`pilot`/`off` production has no ball-checking owner; essential callback failure
fencing remains active. Repeated identical pure-function evaluations may
coalesce one exact candidate observation, but conflicting values/precision still
fail. This is unrelated to duplicate assigned sampling work, whose coordinator
identities and stream partitions remain unchanged.

## Evidence and remaining gates

Reviewed executable evidence includes the public analytic **3/3** gate, empty
and zero-dimensional **4/4**, native root callback **23/23**, exact vector
**10/10**, recipe **17/17** and artifacts **45/45**. Public analytic controls use
real generation, restoration, binding, pilot and kernel APIs with no admission
bypass. They cover both dynamic constructions, complete complex Laurent vectors,
higher endpoint derivatives, symbolic/native-dual Taylor/IBP, the stationary
causal lower lip and policy-invariant values. The original quadrature tolerances
were retained. Earlier family **8/8** and tagged eager/SymJIT controls establish
their recorded source slices, not a substitute for the forthcoming broad gate.

The following are acceptance gaps, not newly identified correctness defects:

1. Run the prepared public CLI dynamic tests through actual ordinary/serial
   workers and checkpoint resume. They exercise QMC with Korobov3 and all three
   validation policies. Following this review, the CLI owner added explicit
   rejection controls for changed S, L and R, unchanged checkpoint bytes on
   failure, and policy/pilot-count-only resume. Opposite construction is tested
   as unavailable singleton selection; rejection within a complete family
   remains a distinct identity control. These new subprocess assertions await
   execution at the next shared Cargo handoff.
2. Exercise dynamic Havana and ordinary discrete MC and the remaining
   periodizations. The native kernel path is method-independent, but source
   reuse is not execution evidence. The subsequent portable/WASM oracle gates
   below cover the public analytic tests, not every interface or workload.
3. Enable the approved full public contour capability family after its gates.
   Current `generate --contour` deliberately selects fixed only; explicit
   `--recipe` selects a dynamic singleton, and `run --contour dynamical=...`
   follows that selected recipe. Native/Python family APIs can request multiple
   recipes, but the final default generation behavior is still pending. No
   alternative recipe is silently substituted.
4. Complete the coherent installed HEPKit host/stub gate for the current source.
   The prior fixed private-wheel results cannot be relabeled as dynamic evidence.
5. Add promised aggregate root-iteration, strength and displacement diagnostics.
   Current public reports truthfully expose policy, pilot coverage, checked
   arguments and maximum certificate precision; they do not yet expose all
   approved performance diagnostics. The runtime owner confirms this follow-up.
6. Complete physical one-, two- and three-loop comparisons, including nonlinear
   envelope terms and positive-factor constraints in public production. Internal
   cubic F/U and certified-bound tests cover those ingredients; simple public
   bubble/linear-F controls do not replace the required physical suite.

Fresh fixed/dynamic repeated-run comparisons now provide useful evidence, but
lower variance alone is not a runtime win. In the reported eight-pair square
control, dynamic variance improves modestly relative to the stronger fixed
baseline while extra sample cost offsets that benefit. Keep actual coordinate
digests, complete vector covariance, both fixed baselines and wall-time
efficiency together when reporting performance. A successful small analytic
comparison does not establish physical multiloop convergence or complete the
implementation goal.
