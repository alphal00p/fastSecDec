# Independent audit of the six massive multiloop references

This read-only review checks the six successful external reports described in `massive-multiloop-diagnostics.md`, the native and historical inputs, and the existing reference bridge. No symbolic process or new numerical integration was run. No normalization, kinematic, transport or real-projection defect was found.

## Scientific input and measure

The frozen reference checkout is clean at `582d8c7f6dde9bf750750d4c2a2d85a94ce940cd`. Direct inspection of all six native/historical graph pairs confirms unchanged internal incidence, external attachment vertices and stable edge IDs. Replacing historical `mass="mt"` attributes with native `particle="phi"` obtains the same mass from the supplied scalar model and massive parameter card. The native cards supply mass one, unit propagator powers, dimension `4-2*eps`, explicit measure multiplier one, and no additional graph numerator.

The two-point inputs have squared external momentum minus one. All four three-point inputs have three squared external momenta minus one; the native independent scalar product is one half and momentum conservation reproduces the third virtuality. The corresponding historical YAML supplies the same complete pairwise products. Internal edge orientations do not change these scalar denominators. No numerator-routing ambiguity occurs in this family.

Native `parametric/scalar.rs::ScalarParametricIntegral::from_graph` supplies the normalized per-loop measure through `(-1)^N Gamma(N-LD/2)/prod Gamma(nu_i)` and the native scalar graph weight exactly once. The reference `_make_loop_integral` supplies the same unit powers and `4-2*eps` to `LoopIntegralFromGraph`. Installed pySecDec `loop_integral/common.py::Gamma_factor` and `loop_integral/loop_package.py` include that same factor, with `additional_prefactor=1`. `ensure_pysecdec_package` does not override it. There is no extra symmetry division, scale or Euler normalization in these inputs.

All six integrals are finite at the supplied Euclidean massive point. Their finite Gamma factors have magnitude one: Gamma(1) for the five-/seven-line cases and Gamma(2) for the six-/eight-line cases. This explains the stated signs. It also limits the evidence: finite coefficients alone cannot experimentally distinguish epsilon-dependent normalization conventions that agree at epsilon zero. Compatibility here additionally rests on the inspected definitions, not merely agreement of six finite decimal values.

## External independence and raw evidence

`FSD.py::_run_native_pysecdec_dot` selects the pySecDec package path before constructing FSD sector evaluators. `src/pysecdec_bridge.py::ensure_pysecdec_package` generates an independent package with iterative decomposition, contour deformation disabled and complex output enforced. `run_pysecdec_package` loads its compiled library, passes the kinematic values, requested accuracy and maximum work, and parses its returned series. It does not invoke the reference's direct Symbolica/SymJIT evaluator; the known experimental real-JIT issue does not contaminate this path.

The raw request metadata contains the general FSD `seed=1`, but `run_pysecdec_package` does not forward that seed. Installed `integral_interface.py::Qmc` defaults to `seed=0`; the generated pylink code reseeds only for a nonzero value, leaving the native C++ `random_device` initialization intact. This supports independent randomization from the native campaigns' explicit seeds. The realized reference seed is not recorded, so exact random-stream reproducibility is unavailable. A frozen fixture should retain this distinction rather than presenting `request.seed=1` as the external integrator's seed.

The bridge leaves QMC `minn=10000` and the underlying default 32 shifts in effect. The requested maximum of 4096 therefore is not an observed evaluation count or a reliable upper bound on the initial work. The raw bridge does not return actual lattice sizes, shifts or evaluations. The diagnostic document correctly preserves that limitation; no performance or matched-work conclusion follows from these reports.

All six successful raw reports have exactly one Laurent order, zero. Their real means/errors reproduce the diagnostic table, and their imaginary means/errors are all exactly zero. Independent `sha256sum` checks reproduce every hash listed in `massive-multiloop-diagnostics.md`, including the successful `.serial.raw.json` self-energy retry. The native reports retain complete production vectors, covariance, completed counts and zero evaluation failures. The earlier six-line discrepancy and later higher-work result remain visible rather than being discarded.

## Typed fixture judgment

A real-only reference fixture is justified for these six points: real masses and Euclidean invariants produce a real scalar integral, and the enforced-complex external calculation reports zero imaginary value and uncertainty. Preserve that observation and the original report hash in provenance. Do not generalize the projection to timelike points or complex weights, and do not synthesize missing negative Laurent orders.

`ReferenceValidation::Checked` may record the independent inspection of input equivalence, normalization, implementation path, raw hashes and transport. Its evidence must explicitly state that these are initial external numerical estimates, not converged or exact reference values. Every positive reported error remains `ReferenceUncertainty::StandardError`; no `Exact` value is warranted. Unknown actual sampling counts and unrecorded realized seeds remain unknown. Use comparison compatibility/independence assertions with their concrete source basis rather than inferring them from the checked label.

The external packages are independently implemented evidence for the native pipeline. A single randomized result and its reported standard error do not prove convergence, validate every estimator tail, or establish a runtime advantage. With those limits retained, freezing these six small typed references is scientifically honest. No actionable blocker remains from this review.

The subsequently created typed fixtures were also inspected. A small provenance correction was requested and implemented: installed `secdecutil/integrators/qmc.hpp` merges dimension-appropriate CBC/PT tables, so the defaults must not identify the sole `cbcpt_dn1_100` table as the selected rule. The recorder now describes that merge, leaves the actual selected rule unknown, and records the wrapper's zero candidate count. The fixture recorder is anchored to the already reviewed raw-report digests, preventing newly generated values from inheriting the checked evidence without another review. This changes metadata only; coefficient values, uncertainties and normalization are unaffected.
