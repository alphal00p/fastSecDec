# Native rational-fiber factory and standalone v15 owner

This slice publishes the complete currently admitted rational one-dimensional
continuation through the existing native kernel/evaluation machinery. It does
not implement the general algebraic resolver, threshold indexed archives,
selective per-cell workers, or global proof replay from a standalone program.

`KernelSet::compile_threshold_fiber` requires a privately constructed
`BoundContinuation`, a fresh staging directory, a Laurent maximum no larger
than the continued request, and valid native compilation/precision policies.
It supports the already certified unit interval and affine delta gauge from two
projective coordinates to one integration coordinate. Exact physical parameters
are constants in both expressions and function bodies; there is no unchecked
runtime rebind. The whole certified cell family remains mandatory.

Each chart's complete Laurent vector is emitted/read with the existing native
Atom/State codec and `RecordRef` writer. The coordinator retains small record
references between compilation jobs. The common private `CompilationInput`
selects an ordinary generated sector or a geometry-neutral coefficient vector;
both use the same `SectorProgram`, compilation job/completion, native backend,
precision rescue and saved evaluator. No fake `SectorMap`, second integration
loop, alternative differentiation engine or polynomial algebra is introduced.
Native Horner ten remains the default. The factory still retains its global
continuation certificate and final resident kernels; record granularity does
not establish bounded global CAD or full serial-publication memory.

The immutable threshold owner carries the closed contribution inventory,
original/projective/cell/endpoint lineage, fixed rational fiber, requested
Laurent layout and resident scope independently of legacy generation metadata.
The common result manifest exposes both original extent and contribution
selection; selecting contributions or exact offsets never promotes a partial
result to the full original integral. Zero in a requested Laurent layout is
explicitly not a certificate that the integral vanishes identically.

The optional v15 envelope extends the existing native Atom/State payload and
supports the existing optional primary-cache wrapper. Legacy emits/read paths
remain unchanged. `ThresholdV1` is appended after all historical recipe variants;
frozen JSON names and serde/bincode ordinal controls preserve their tags.
Restoring/evaluating v15 uses the feature-neutral kernel owner; only creating a
threshold artifact requires the GCAD feature. Indexed writer/partition paths
currently refuse threshold owners explicitly. The Python recipe label is an
inspection adapter; no new Python/CLI generation entry is implied.

The semantic identity excludes native State bytes, native evaluator bytes,
transport record hashes and compilation-job grouping. It binds canonical
original source identity, fixed bindings, maps, domain/chamber, complete
continued expressions and function bodies, continuation policy, requested
layout, compiler/precision policy and resident selection. The current bridge
has exactly one ordinary Numerator role, with deterministic source/epsilon-body
slot tags. Native DERIVATIVE retains its builtin head; definitions are sorted
by (slot, derivative order), never by process-global Symbol IDs. Unassociated
multiple ordinary heads are refused. Original physical symbols are not renamed.
The endpoint witness separately binds the actual normalized powers/prefactors,
closed units and endpoint values, numerator closure, common epsilon strip and
Gamma-pole witness; it is not merely an interval-coverage digest.

Native load validation checks layout, structure, expression-table bounds,
fixed rational values, runtime-empty schema and envelope/digest claims according
to the existing optional validation policy. It does not reconstruct global CAD
or continuation mathematics. `require_global_proof` returns `ProofUnavailable`;
arbitrary supplied metadata or transport records do not gain native factory
authority. As with the existing native evaluator codec, executable bytes are a
trusted compatible-builder boundary, not a hostile-IR sandbox.

The shared conservative exact classifier refuses reachable nested aliases.
If the root references no aliases and no integration coordinates, its unused
alias table cannot change its value. The native `AliasedAtom::into_inner`
implementation rewrites only the root until stable; a direct executable control
also checks an unreachable cyclic table. This narrow constant-root case preserves
ordinary exact-only results. A root referencing aliases still receives the
conservative all-body check, preventing hidden coordinate dependence or an
unchecked cycle from being materialized. Native evaluator construction remains
responsible for recursive-alias refusal. The pole-only control checks the full
mathematical value independently of storage partition; a genuinely empty
requested Laurent range restores as zero-in-layout with no stochastic kernel.

Validation used a private copied core against the actual c540 native dependency
graph, based on 3733594 plus the unchanged registered fa1fc0a epsilon-numerator
successor. No protected release binary or shared Cargo output was overwritten.
The final distinct gates passed: nine threshold factory tests, 56 native
artifact controls (three existing ignores), 14 native-program controls (six
existing ignores), one detached compilation owner, one conservative alias
classifier, one ordinary complex result projection, and two cancellation
controls: 84 passed. Strict copied-core/test Clippy and formatting passed.

The factory controls cover both native Eager and SymJIT, complete complex vector
and save/load parity, fresh-process native State restore, source-term and actual
epsilon-numerator three-slot identity across fresh unit/helper registrations,
coefficient/precision refusal before staging, requested-layout zero, partial
result scope and unsupported indexed publication. The native HEPKit graph
bubble includes its Gamma/rGamma prefactor and affine projective preparation;
a restored v15 owner sampled through the ordinary `QmcSession` gives
`[1, 0, 0.35208156699783544, 1.5707963267948966]`, matching OneLOop's complete
pole/finite real-imaginary vector in that control. No general convergence or
performance conclusion is drawn from this small analytic fixture.

The early private failures are retained: a pole control initially assumed
exact-only storage despite unused coordinate aliases, and initial strict Clippy
reported the size difference of the new job-input variants. The former now
checks the correct mathematical/scope contract; the latter has a narrow
commented allowance preserving the directly owned legacy job rather than adding
one allocation per legacy sector solely for the optional variant. An initial
recipe-first draft was corrected before publication and covered by the frozen
wire regression. Runtime's independent native-record/compiler/owner source
review passed at this scope. The integrated portable source-selection gate then
caught the over-conservative treatment of unused aliases in an existing exact
result. The root-without-aliases case above fixes that regression; reachable
nested-alias safeguards remain. Consumer builds also required explicit set types
with Python's wider dependency graph and an exhaustive recipe match in a
portable contour-only fixture.

Registered milestone checks pass: 552 native library tests (20 existing
ignores), 88 host-portable tests, 14 native saved-result/scope tests, three CLI
result tests, and the isolated Python binding build. After the alias correction,
its direct regression and all nine threshold factory controls pass again.
Strict workspace/all-target Clippy with threshold support and workspace
formatting pass. These are native and host-portable checks, not fresh WASM
execution, installed-wheel tests, serial threshold acceptance or a general
resolver milestone.
