# Native v10 dynamic recipe ownership contract

Implementation contract coordinated with generation and runtime owners after
51 native contour foundation tests passed. This document does not advertise
production support for the dynamic prescriptions.

## Explicit recipe and mathematical settings

The selected native payload identifies its recipe explicitly: undeformed,
fixed-v1, dynamic-polynomial-v1, or dynamic-sign-aware-v1. V2 directory selection
happens before this payload is decoded or JIT translated. Native v9 remains
readable with its existing exact layout, identity and fixed-strength semantics.
Parameter-name inference remains confined to adapting old v9/v1 artifacts.

The dynamic schemas reserve the existing native symbols for safety fraction S,
strength cap L and displacement cap R. They are mathematical runtime inputs,
separate from physical parameters; optional validation policy and pilot evidence
remain outside mathematical identity. Rebinding these values only binds saved
program inputs. Dynamic admission stays an explicit unsupported error until the
complete map, root and validation path passes its native gate.

## Owner descriptor

A native program descriptor owns immutable `RootProgram` objects throughout
mapping, subtraction and compilation. An Atom containing a callback tag is not
an owner. Every root helper has a version, dense coefficient count and digest,
and contains the native optimized H/Hu evaluator and its serialized native bytes.
The full-sector coefficient schema cannot shrink after taking a subtraction face.

A per-chart recipe descriptor retains:

- local source-chart identity and full sector dimension;
- ordered odd F orders and ordered even orders for each positive U;
- their structural counts, dense coefficient count and maximum even order;
- the fixed smooth regularity value and selected root-helper digest;
- each U's exact closed-cube lower bound and the native proof kind;
- the S/L/R runtime input identities.

The existing chart metadata already retains F, U, images, endpoint ratios,
Jacobian and actual face restrictions. Do not copy the complete symbolic envelope
into another owner merely to attach the descriptor. Metadata-only catalogue
inspection must not decode these rich sector records.

## Saved checker preparation

Prepare and persist check programs during original generation. The polynomial
baseline outputs the direction norm squared, Bk bounds, undeformed U values and
even U ray coefficients. The sign-aware program additionally outputs each
weighted matrix's mean and squared spectral gap, and the harmful normalized U
coefficients. This supports independent bound and radius validation without
reconstructing symbolic envelopes or trusting rounded positive-part callback
results after reload.

Optional certified validation must not evaluate unsupported transcendental
operations in the ball domain. Algebraic enclosures for the sign-aware square
roots need their own independently reviewed admission, using native numerical
root refinement and certified polynomial sign inequalities. Ordinary error
tracking is insufficient. Fixed check programs and their accepted v9 behavior
remain unchanged.

## Restoration and selective records

Native v10 saves helper bytes separately from its main optimized evaluator.
Decode helpers and retain their owners before numerical callback construction.
Restore native H/Hu directly; never rebuild its symbolic expression or rerun
Horner/CPE while loading. The coefficient-only helper has no callbacks, preventing
recursive workspace acquisition. A weak routing registry resolves digest tags
but cannot retain a closed sector's numerical workspace or source expressions.

Each selective sector/exact record contains only its relevant descriptors,
helper owners and check programs. Source chart remapping applies equally to
recipe metadata, validation faces and checker chart identities. Exact-only and
literal-zero records must preserve the selected recipe without claiming checks
that were not performed. The returned selected owner keeps a one-recipe portable
cache; no dormant second evaluator program is added to `SectorKernel`.

V2 record receipts need explicit recipe identity for v10 payloads. The directory
and decoded native descriptor must agree; recognizing S/L/R names is not a
capability check. Old v1/v9 receipts remain readable through their established
legacy classification. Dynamic records are never disguised as a synthetic v1
catalogue with overlapping or remapped physical byte extents.

## Sampling diagnostics and failure lifecycle

Root counters should record solves, iterations, preparation and precision rescues
at existing caller-owned update boundaries. They are observational and do not
enter sampling statistics or identities. The bounded native callback failure
slot must be cleared per attempted numeric domain; an f64 failure cannot poison
a successful DD/Float rescue, and a later successful callback in the same failed
attempt must not erase its earlier diagnostic. Solver termination and finite,
positive physical strength admission remain active with validation disabled.

## Implemented storage foundation and remaining admission gate

`kernel/recipe` now owns the explicit descriptor. The v10 payload wraps the
unchanged v9 payload layout, preserving all existing v9 writes and semantic IDs
by default. `KernelSet::declare_program_recipe` permits explicit static-recipe
roundtrips; it cannot manufacture dynamic capability. V2 worker receipts carry
an explicit recipe only for v10 records, and catalogue/load admission checks
that the descriptor and receipt agree even when digest checks are disabled.

Dynamic chart descriptors retain the exact Rational positivity lower bounds,
full dimension and derivative orders. Zero-dimensional exact charts retain
their recipe with empty derivative-order sets. Compact exact setup discovers
root-helper tags through native Atom symbol traversal and retains only helper
owners referenced by exact offsets, while dropping rich chart metadata.

Independent reviews confirmed the structural order formula and helper lifetime
boundary. Before removing the explicit dynamic runtime-admission rejection,
bind every descriptor's chart index, dimension and positive-factor count to the
retained native generation metadata and its actual checker requests. Corrupt
association regressions and the complete dynamic map/radius/check path remain
mandatory; internal descriptor consistency alone does not prove these links.

The focused native descriptor gate passes five tests, including 0D charts and
exact-offset helper lifetimes. The artifact gate passes 37 tests, covering v9
identity preservation, explicit v10 static roundtrips, fixed pilot associations,
receipt/descriptor disagreement and existing selective/corruption controls.
The final workspace gate will use the coordinated public owner revisions.
