# Checking the discriminant prerequisite for algebraic ramification

The native quasi-ordinary preparation stage accepts an exact polynomial of any
admitted degree on an actual regular chart. It keeps the complete polynomial
and coordinate/parameter roles. It does not solve the ramification problem or
certify a root branch over a whole real cell.

Coefficients may contain inverses of existing checked guards. The existing
native rational-conversion helper clears those denominators and verifies each
coefficient identity. Let `B=D*P` and let `b` be its leading coefficient. Both
`D` and `b` must already be units in the original localization. The change
`T=b*z` gives a monic polynomial satisfying `Q(b*z)=b^(n-1)*D*P(z)`.
Failure of the leading-unit check retains a degree-drop/leading-stratum result;
the implementation never manufactures a new inverse to bypass that locus.

Native differentiation and resultant compute the discriminant. Its principal
ideal passes through the existing Cartier-factor extractor on the supplied
SNC ledger. Admission additionally requires the residual factor to be a unit
in that same original localization. A repeated polynomial, disconnected
unequal powers, missing unit or resource stop retains a distinct outcome and
its completed evidence. None represents a zero contribution or an endpoint
certificate.

API/source inspection and native probes cover the resultant composition,
exponent widening, coefficient clearing, exact division and original-unit
membership. No polynomial, factorization or root algorithm is duplicated.
Native intermediate allocations still require caller-owned process limits;
conservative term and degree bounds can refuse a sparse high-degree input.

Root and the independent resolver agent reviewed the source and mathematical
scope. Ten new test groups pass in the isolated native suite, alongside 79
inherited tests, with strict Clippy. Controls include `z^5-x`, crossing
discriminant divisors, actual guard inverses, repetition modulo a nonlinear
relation, disconnected multiplicities, wrong owners and resource exhaustion.
A non-binomial `z^5-z-x` control retains its exact local factor germ. A supplied
`x=t^5` substitution is explicitly a feasibility control, not automatic
Abhyankar–Jung recursion.

The joined threshold suite passes 152 tests (one ignored child entry), with
strict library/test Clippy. A second independent integration/reuse review
confirmed the original-localization unit checks, degree-generic scope and
retained non-admitted outcomes; it found no duplicated CAS or unsupported
endpoint authority.

Automatic valuations, ramification and splitting, real branch transport,
parameter strata and closed-face endpoint certification remain required.
