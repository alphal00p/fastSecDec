# Universal recipe-family generation

Implementation and independent source reviews pass. The public contour switch
still requests the fixed recipe only. Dynamic recipe storage is not dynamic
runtime admission.

## Shared caller-owned orchestration

The CLI's internal `generate_family` entry accepts an explicit capability set
and default. It canonicalizes the set and rejects empty/duplicate selections or
a default outside the set. Journal schema three persists that complete request
before checking whether a prior generation completed. Resuming with changed
worker count or recipe order is allowed; changing the family/default, scientific
input, build or owner identities is refused before adopting results.

Shared native preparation builds geometry and durable complete chart sources
once. Each recipe then uses the same extracted pipeline for ordered exact
symmetry, native subtraction-formula preparation and fused sector completion.
Job names contain the recipe; immutable requests and receipts additionally bind
its exact execution-source digest. Physical source identity never substitutes
for that execution-context fence. Completed workers return compact receipts,
not evaluator objects. One native `ProgramArchiveWriter` stream-copies the
records, and the existing immutable-data/atomic-manifest transaction publishes
only after every requested recipe is complete.

Ordinary generation uses the same universal v2 native archive. The native owner
partitions the already compiled kernel set once, adopts its selected recipe
identity and retains portable bytes without decoding/JIT. The CLI borrows those
bytes into a temporary staging file and uses the same publication transaction.
The ordinary generation scheduling and resident kernel return remain intact.
Legacy v1 readers and dedicated historical fixtures remain supported.

## Observations and selection

Optional generation observations are keyed by recipe, including source-chart
routes and formula reuse. Shared timings remain on the archive; recipe-specific
wall intervals remain separate. All observations are excluded from mathematical
and checkpoint identities. Ordinary generation retains its existing bounded
human inspection preview under the matching recipe key. Selecting another
recipe never borrows that preview. Deep inspection continues to use the native
selected-record reader.

## Next public-interface dependency

The native single-recipe `GeneratedIntegral`, `GenerationSession`, compilation
jobs and `KernelSet` remain the inner owners. A caller-driven native family
owner is needed before the HEPKit wrapper can mirror complete capability
generation without implementing orchestration in Python. Explicit native
archive selection already avoids decoding unselected programs.

The artifact's default recipe and `run`'s requested resident recipe must stay
distinct. A completed contour-capable family should permit undeformed runtime
execution by default; requesting fixed/dynamic integration selects that
specific owner before loading or compilation. Ordinary generation must return
the requested existing compiled owner without decode/re-JIT for selection,
while other completed recipes can be serialized and released. This requires a
narrow `main` Run call-site change alongside the future native family owner.
None of these future public changes are advertised by this checkpoint; the
existing public contour flag still requests a fixed singleton.
