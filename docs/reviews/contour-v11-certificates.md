# Native v11 certificate transport

This increment stores independently optimized dynamic-check arithmetic and its
full-sector mathematical context. The original transport gates kept dynamic
execution closed; the later lifecycle and public scientific acceptance below
now admit validated v11 records. Transport checks alone are not causal proofs.

## Ownership and compatibility

The existing native v9 payload and v10 descriptor retain their exact layouts.
A distinct v11 magic/version wraps the payload with explicit certificate storage;
`None` remains legacy/source ownership, while `Some([])` is an explicit empty
v11 context. Native Symbolica evaluator codecs and helper restoration are reused.
Loading does not reconstruct expressions or repeat Horner/CPE optimization.
Compiled certificate owners cannot silently downgrade into source-only staging.

Each saved instance carries an optional local chart projection, canonical
mathematical namespace, full-sector proof structure, coordinate/runtime schema,
causal/positive-factor identities, recorded faces, and saved raw/combiner programs.
Proof/helper/source association is checked independently of optional transport
hash validation. The retained metadata is checked before constructing numerical
kernels. Runtime admission remained closed during the original transport increment.

Equal namespaces may occur in distinct charts or independently optimized records.
Their canonical proof, factor, coordinate, runtime and component schemas must
agree; their native program byte order and face subsets may differ. All retained
instances survive. The numerical checker must validate a candidate against each
matching context, rather than arbitrarily choosing one byte representation.

Selected records retain projected instances and the contexts referenced by
surviving exact callback requests. Every surviving exact face must be covered by
at least one matching saved context. Context-only helpers remain owned even after
rich chart metadata is released. Removed exact requests release their certificate
programs and otherwise unused helpers. Chart remapping changes only the optional
reporting projection; it does not change the immutable namespace or full-sector
proof. Merging rejects mixed legacy/certificate ownership and conflicting context.

## Exact mathematical associations, 2026-10-10

The next additive v11 field stores each exact mathematical root Atom with its
separate diagnostic namespace/face bundle. Exact coefficient Atoms remain
untagged. Native assembly sums them before selecting surviving roots, unions
contexts for native-equal roots, and discards associations and unneeded helpers
when the roots cancel. Stochastic records do not retain exact associations. The
native State export and v11 semantic identity include this field; legacy v9/v10
layouts remain unchanged. Generation-to-bytes uses the same prepared dynamic
checks and late stochastic lowering as resident compilation.

This replaces an unregistered proposal to retain numerical exact programs per
original record. A focused native counterexample demonstrated that separately
evaluating or composing those programs loses cancellation of singular terms in
a surviving coefficient. The implementation retains the existing mathematical
sum instead. The supported whole-function value map preserves numeric domains
and uncertainty, but blanket prebinding would violate lazy conditional
evaluation. The [native cache audit](contour-exact-map-audit.md) records the
public API/source/probe evidence and the narrowly scoped owner API proposal.

The recipe filter passes 16 tests (one child-only entry is ignored), including
equal polynomial radii for opposite causal polynomials with different namespaces
and partial/total exact cancellation. The association transport fixture initially
had no surviving exact root after native simplification; its nonempty assertion
correctly failed. The strengthened fixture explicitly inserts a genuine native
generated face-radius Atom into a test-only exact coefficient, so it tests codec
ownership rather than claiming a physical exact-contribution example. Its
fresh-process transport check and the new explicit v10 dynamic regeneration
guard await the next gate. Static legacy v9/v10 readers remain unchanged.

Numerical exact binding will consume only the owner's actually executed root
values; it must not infer execution from a function in an unselected conditional
branch. The owner direct-vector API has passed independent source review and
focused native-domain/lazy-evaluation tests; consumer adoption is a separate
gate. Strict stochastic request completeness must not be reused to demand
execution of exact roots in untaken branches.

## Full-source coordinate projection, 2026-10-10

A separate native generation probe uses two source coordinates, causal
`F=1/4-x`, and the retained positive declaration `(1+y)^0`. It includes the
production request-lookup source unchanged and uses public generation/metadata
APIs. In eight regular/x-endpoint-pole combinations across symbolic/numerical-dual
generation and Taylor/IBP, the native coordinate map sends `x` to `t1` and `y` to
`t0`. The radius is independent of `t0`, while its full source still retains
`U=1+t0`. Every generated stochastic sector has both inputs; the lookup retains
the interior request and, for the pole case, the `x=0` request. No exact root or
actual missing integration input occurs in this control. This evidence is not a
reproduction of a generation failure.

Four additional inert-`y` endpoint-pole controls preserve the same two inputs and
have no exact roots. Native equality merges their radius associations into one
bundle containing both the interior and `y=0` restrictions. This is direct
evidence that all matching full-source contexts must survive even when the
mathematical radius is independent of the restricted coordinate. The separate
probe sources/logs are ignored build artifacts; no alternate algebra or
generation path was introduced.

The separate checker projection mechanism encloses any absent source coordinate
by native `[0,1]` ball arithmetic, with explicit face restrictions overriding the
interval. It must prove the full saved source uniformly, or return unresolved;
it never chooses an arbitrary representative coordinate. Independent source
review found the attempt-local restoration, per-owner scratch and all-context
validation coherent. The initial checker test fixture incorrectly used original
symbols instead of mapped target symbols; the corrected controls identify the
actual mapped symbols and pass the reduced-axis, dependent-factor and
permuted-face checks. The focused native checker/attempt suite passed 11 tests,
and the v11/legacy binary suite passed 15 tests with one subprocess entry
deliberately ignored in the parent process. These are source-local gates before
the current combined numerical-owner validation. Production dynamic admission
remains a later gate.

### Bound checker inputs and pilot receipts

An independent receiving-owner audit found that matching input arity alone did
not bind the certificate's ordered physical inputs. Native descriptor admission
now parses the saved names into Symbolica symbols and compares the complete
ordered list with the receiving kernel's runtime inputs. The dynamic binding
repeats that boundary check before capturing numerical values. A regression
exchanges two physical parameters while keeping all deformation controls in
place, including a context-only exact owner. The native recipe gate passes
17 tests with one intentionally ignored subprocess entry, including this
ordered-input regression.

Pilot plans capture immutable native specifications and their actual sector or
exact evaluation points. Only synchronous execution of a plan constructs its
private receipt; acceptance consumes both handles and checks the binding epoch
and a unique plan token before modifying coverage. This prevents a receipt from
another point, binding clone, or previous same-point plan from unlocking the
pilot. Partial execution yields no receipt. Native validation supplies the
numerical evidence; the token only establishes its lifecycle. Immutable
specifications are cached per resident binding, while numerical pilot-owner
caches belong to the runtime wrapper. Production evaluations use neither pilot
tokens nor this plan machinery. The five focused binding tests pass, including
foreign/replayed receipts, partial-owner failure, complete native scope
associations, source-projection/count consistency and structural request
admission with validation disabled. The larger lifecycle filter reached
17 passing tests and exposed a separate valid-artifact spelling mismatch in
the remaining test: saved `Symbol::get_name()` strings differ from canonical
Atom spellings. Loading now relies on the already-enforced ordered native Symbol
comparison, retaining declared physical parameters and all factor/metadata
checks. The corrected complete lifecycle gate passes all 18 tests, including
actual eager/SymJIT restored pilots, policy changes, counters and atomic failed
rebinding. The initial public scientific gate exposed repeated identical root
calls in native direct translation. Observation now coalesces only equal exact
candidate centers at identical precision, preserving conflicting-candidate
failures; the separate owner optimization is recorded in the
[external-cache review](contour-direct-external-cache.md). The repaired public
scientific gate passes all three tests, including eight endpoint/subtraction
combinations, complete complex vectors and threshold policy agreement. The
callback filter passes 23 tests and the empty/zero-dimensional generation filter
passes four tests. These focused gates do not replace the remaining physical
multiloop, interface and performance acceptance work.

The current positive-residual admission requires an exact rational native
polynomial with nonnegative coefficients and a strictly positive rational
constant. Its certified lower bound therefore cannot become stale after a
physical-parameter rebind. General parameter-dependent positive residuals are
explicitly unsupported by this construction; no arbitrary positive floor is
substituted. Graph-derived residuals meeting this native proof criterion are
supported. Source
review confirms unchecked numerical owners capture no certificate specification
or ball workspace, while mandatory physical-input checks and essential callback
failure fencing remain active. Runtime overhead measurements remain pending.
