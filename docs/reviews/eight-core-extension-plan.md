# Extending the highest-order accuracy measurements

This is a source-only plan. It adds no runner, estimator, production option or
new execution. The first triangle/box eight-worker reference smoke failed during
Symbolica worker initialization; the same environment constraint applies to any
Pathfinder eight-process extension until a supported setup is available.

The existing completed-allocation ladder remains appropriate: caller-owned CLI
orchestration, native QMC estimates, all coefficients retained, maximum signed
requested order as the timing target, fixed independent seeds and no pooling
different lattice sizes. Keep Kuo33002/linear/full-support/Korobov3 explicit for
this baseline. HKKN or another lattice would be a separately prescribed
optimization comparison, even though the existing holdout already supplies
useful quality evidence. Do not change a lattice after observing a slow row.

| Cases | Largest requested order | Independent scientific status | Next eligible measurement |
| --- | ---: | --- | --- |
| Six massive kite/self-energy/three-point fixtures | 0 | Versioned checked external references retain positive errors; native complete finite vectors and the 72-row holdout were reviewed | Same fixed-count accuracy ladder after fresh preparation and a supported eight-worker reference smoke |
| Massless on-shell double box | 0 | All five orders -4 through 0 checked against the separately generated pySecDec package; leading exact-zero proof is separate | Full-vector -4..0 ladder; finite part is the timing target, with leading pole retained |
| Off-shell triple box, scalar and rank-two numerator | 0 | Native original/projected exact family identities and complete allocations exist; independently accepted external full vectors remain pending | Native observed-error diagnostics may be reported, but matched reference-checked accuracy acceptance waits for those references |
| Issue 1, complete seven-dimensional positive orthant | +2 | Native complete orders [0,1,2] allocation exists; independent full-orthant reference is pending | Execute the already reviewed bounded external reference first, then prescribe the order +2 ladder |
| Hard four-loop, complete nine-dimensional positive orthant | 0 | Native complete allocation exists; independent full-orthant reference is pending | Same scientific-reference gate before matched accuracy acceptance |
| On-shell triple box | 0 | Full generation remains incomplete in bounded original/projected attempts; representative pointwise oracles do not establish the integral | Resolve complete generation and independent full-vector science before an accuracy-time claim |

For the six massive cases, existing native cards and `FSD.py generate` /
`integrate --output BUNDLE` already provide the necessary drivers. Their fixed
physical inputs are mass one and external virtualities minus one, dimension
4-2*eps and normalized per-loop measure. The reference DOT CLI can receive its
existing graph/kinematics files with `--mode massive --m 1`; no new graph parser
or pySecDec package generation belongs inside the timing loop. Native generation
must use the current frozen CLI so its artifact/dependency validation remains
active. Keep generation and loading separate from integration as in the small
protocol.

`src/result_io.py::target_from_result_file` already accepts the retained external
raw reports' `pysecdec` block, including explicit orders and errors; it does not
understand the native versioned `ReferenceResult` envelope. Use the existing raw
report as the Pathfinder transport and the audited native fixture for native
comparison, binding both to the same source evidence. Do not add a second error
calculator. The Pathfinder `_align_target_to_topology` helper pads missing
orders with zero: an outer review must therefore use the original reference key
set, not treat its padded target entries as independently measured zero values.

The current smoke reader is intentionally triangle/box-specific. A future
adapter can reuse its native saved-result validation and native `compare`, but
must replace the hardcoded `[-2,-1,0]`/three-count layout with explicit order keys.
Massive native output is `[0]`; historical reference output can include inactive
negative padding. Check every declared active coefficient's complete R shifts
and preserve inactive coverage as such. A missing key is not an implicit zero.
Double-box checks must retain all five keys, not only the timing target. External
cross-order covariance remains unavailable where the reference never exports it.

The source direct-U/F route supports prepared FSD integration, but its independent
pySecDec lane is a different public interface: native `disteval`, with adaptive
per-kernel work and a deadline. Its initial requested N/R are not final work and
it cannot be relabelled as the fixed-count FSD/Kuo benchmark. Both issue 1 and
hard-four-loop cards must retain `geometric_infinity_no_primary`, all-sector
scope, the complete positive orthant and global prefactor one. A single raw
sector cannot stand in for the full integral. Existing launchers and normalization
limitations are documented in `remaining-reference-protocol.md`.

Off-shell projected triple-box references use the existing pySecDec
`LoopIntegralFromPropagators`/`IntegralLibrary` path, since the frozen DOT parser
does not admit zero powers for the inactive repeated lines. Native
`partial_fraction`/`sector` owns the exact projection; the external constructor
owns its raised-power measure. Keep the original and projected representations
explicit in any cost comparison. The checked repeated-family identity is not
an independent numerical reference for the higher coefficients.

Before extending execution, prescribe bounds suitable for each full allocation
and retain timeout/work-limit outcomes. The same 0.1% observed-error inequality
applies to a nonzero maximum-order coefficient; an analytically zero target
requires a separately specified absolute tolerance before sampling. Each accepted
result must retain complete support, full native covariance, precision/replay
policy, actual counts and exact source/build identity. A checked transport and a
small residual pull remain correctness evidence, not proof that reported errors
are calibrated.
