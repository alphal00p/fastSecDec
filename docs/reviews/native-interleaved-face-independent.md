# Independent interleaved-face boundary review

The reviewed `series_first/named.rs`, `named/interleaved.rs` and associated
controls introduce no actionable cache or exposure finding. The parent
`subtraction::series_first` module remains behind `#[cfg(test)]`, and original
resolution remains the default. The source findings below are supplemented by
independently inspected small-gate evidence; they establish no performance gain.

Admission checks every argument against its own original coordinate, exact zero
or exact one and requires at least one face. Swapped coordinates, composed
arguments, other constants and face-free requests preserve the original native
mixed-partial followed by simultaneous substitution. Zero-depth faces run
before differentiation; each positive-depth axis receives all its requested
native derivatives before its own face substitution.

Only the complete `(source, depths, arguments)` request cache receives a
specialized result. The unsubstituted `(source, depths)` partial cache remains
exclusive to the original fallback. The new controls deliberately reuse the
same source/depth under different faces and then an unsubstituted or composed
request, and check route counters, repeated hits, nonzero mixed derivatives and
native exact zero. This meaningfully tests the contamination boundary.

Argument shape alone does not prove regularity at a singular face. The stated
admitted regular-coefficient scope is therefore essential: this is a restricted
reordering of native derivatives and literal evaluations, not an endpoint-limit
algorithm or broader singularity admission. The existing notes preserve that
limitation. Small symbolic controls, full-vector program and fresh-process
checks, and independent original-expression oracles remain distinct gates;
none establishes a whole-graph speedup by itself.
