## Actual precision metadata correction

The first actual original-input adapter attempt subsequently reached all seven
numeric comparisons but failed an export assertion: a requested 512-bit
evaluation returned native component precisions `[505,511]`. No complete oracle
record was accepted. Numerica's native Float arithmetic tracks precision through
operations; subtraction can reduce it and square root can increase it. Its
ordinary `Display` output also explicitly does not promise reconstruction of
the stored value. The earlier small gate remains valid for its measured inputs,
but its fixed-output-precision assumption was not a general transport contract.

The additive dual reader now distinguishes requested evaluator settings from
positive actual precision for each real/imaginary component. It parses the
adapter's native `as_raw().to_string_radix(10, None)` text at the recorded actual
precision and requires exact native export/import value and precision equality.
There is no precision padding or assumption that actual precision cannot exceed
the request. The actual reader's dual reference value also uses its recorded
precision; the legacy Series-v1 reference parsing and all comparison tolerances
remain unchanged.
