## Source-owned pole bound and exact admission

The captured endpoint powers are
`[0,-3-3*eps,-3-3*eps,-3-3*eps,0,-2-2*eps,0,-3-3*eps,-1-eps]`.
The six regulated singular axes are zero-based 1, 2, 3, 5, 7 and 8. The bound
`B = 6` comes from the frozen original Taylor construction, not from either
attempt's width-one series result or from candidate output:

1. `generation/subtraction.rs` adds at most one affine endpoint denominator
   `a + degree + 1 + b*eps` for each selected boundary branch at each singular
   axis. A branch does not accumulate every degree's denominator. Its nonzero
   slope yields at most one zero-center pole per axis.
2. Later coordinate differentiation does not differentiate epsilon or existing
   endpoint denominators. Derivatives of the captured positive residual
   polynomial powers add polynomial factors in their affine exponents and
   inverses of residual polynomials; they introduce no further epsilon poles.
3. The common `Gamma(4+3*eps)` is regular at zero. Exact domain admission must
   establish regular residuals at the particular prescribed point for all
   already substituted faces represented in the imported original expression.
   Addition cannot worsen this conservative branch bound.

After binding one exact point into the original Atom, call native
`collect_factors` without global expansion and form
`analytic = factored_original * eps^6`. Native normalization owns equal-base
power cancellation. Do not infer safety from the final scalar value, final
finite output, an approximate leading zero, or the source bound alone.

The shared helper must visit the whole resulting Atom graph and fail closed:

* Exact native rational or complex-rational constants only; no approximate
  input coefficients and no unrecognized symbols/functions.
* Every negative integer power has an exactly nonzero scalar base at epsilon
  zero. Every noninteger or regulator-dependent power has a strictly positive
  real exact scalar base at zero. Admit both base and exponent recursively.
* Each logarithm has a strictly positive exact scalar argument at zero; Gamma
  has a strictly positive exact scalar argument at zero and the native expected
  arity. Unknown functions, a remaining singular Gamma, or a center that native
  literal substitution cannot establish as exact are failures.
* Positive integer powers are analytic once their children are admitted; this
  does not excuse an inverse or unsafe function beneath them. Native numeric
  evaluation never substitutes for these exact intermediate checks.

Retain hashes and native exports for the point-bound, factored and analytic
Atoms. Distinguish native factor collection's algebraic identity from the
explicit monomial reversal checked by the small helper. If the reversal or
admission fails within the bound, retain the failure and stop this route.
Do not expand the 137-MB input merely to compare alternative representations.

## Components, coefficient rows and provenance

Build the regularized native evaluator with the accepted small helper's native
options and a single regulator parameter. Use exactly the ancestor-closed
scalar-first shape `[[0],[1],[2],[3],[4],[5],[6]]` and require seven native
outputs. The regulator seed is the seven-component vector `(0,1,0,0,0,0,0)`.
Native shape components already are Taylor-normalized; component `j` supplies
the original Laurent order `j - 6`. The complete output layout is always
`[-6,-5,-4,-3,-2,-1,0]`, including cancellations and numerical zeros. Never
trim a leading zero, assume a numerical zero is exact, or reduce the layout to
the candidate's observed orders.

The source pole bound, complete exact operation admission and native Taylor
shape together provide analyticity coverage through original order zero.
They do not provide `Series::absolute_order`, a native trailing order, an exact
nonzero-order list, or exact symbolic coefficient Atoms. Do not invent these
fields. The evaluator build/vectorization may reject a native operation; that
is a recorded unavailable route, not permission to supply custom derivatives.

Clone and map the exact native evaluator independently at 512 and 1024 bits;
do not derive the second run by raising the first run's precision. Require
finite real and imaginary parts and per-component agreement with the existing
scaled `1e-70` rule. For this real input, preserve imaginary outputs in the
record and verify agreement with zero rather than silently discarding them.
These checks establish numerical stability, not exact vanishing or equality to
the named candidate. The small control's tiny-value guard remains part of the
helper gate; the actual adapter must never use its unit-floor tolerance to
classify a coefficient as structurally zero.

Preserve the existing numerical row keys `order`, `value_512`, `value_1024`,
`absolute_precision_difference` and `precision_agreement`; add explicit
imaginary values/checks and the native component index. Any exported MPFR Atom
must be labeled approximate, include its precision and digest, and must not be
called an exact coefficient export. HEP's concrete source review required an
additional storage check: each evaluated real/imaginary component's actual
precision must equal the requested precision. Nonzero native Float exports
must survive native export/import with equal values and component precisions.
`Atom::num` canonicalizes a numerical Float zero to `Atom::Zero`, so that storage
case is explicitly labeled `native-canonical-numeric-zero` with null stored
precision. It certifies neither an exact source zero nor retained Float
precision. Every numeric export sets `symbolic_zero_certified: false`.
Retain the native exact vectorized program
through an existing native codec if that export is needed and available under
the exact linked feature identity. The reader consumes the numerical rows, not
the old `coefficient_file` fields, so native exact symbolic coefficient recovery
is not a reason to add another expression-reconstruction algorithm.

## Reader coverage variant

`output/probes/actual_named/reader.rs` consumes the required source/capture/
point identity and numerical coefficient rows. Its full signed-order union,
512/1024-bit checks, exact-point comparison, rounded-input reference, cold
reload, worker clone, weights one and `1e40`, and forced replay checks can all
remain unchanged. It already reads and validates all three oracle records
before running any point comparison.

However, the unchanged reader also requires format
`native-original-taylor-point-first-oracle`, version one, and
`native_absolute_order > 0`. That field in
`output/probes/point_first_original_taylor.rs` is explicitly emitted from
`Series::absolute_order()`. Native dual coverage cannot truthfully supply it.
Writing `"1"`, relabeling a dual result as the old native-Series result, or
constructing a superficial finite polynomial solely to obtain that metadata
would hide the change of certificate.

Therefore complete record compatibility with the unchanged reader is blocked
by its coverage admission contract; the coefficient layout is compatible. The
coordinator accepted a source-level proposal for an additive coverage variant,
with HEP's agreement. The old Series-v1 branch and every numerical comparison
remain unchanged. The prospective new format is
`native-original-taylor-dual-oracle`, version one, with coverage fields:

```json
{
  "coverage": {
    "kind": "source-pole-bound-and-native-analytic-taylor-shape",
    "source_pole_bound": 6,
    "source_singular_axes": [1, 2, 3, 5, 7, 8],
    "regularizing_monomial_power": 6,
    "exact_intermediate_admission": true,
    "native_monomial_roundtrip": true,
    "native_component_shape": [[0], [1], [2], [3], [4], [5], [6]],
    "component_count": 7,
    "minimum_retained_order": -6,
    "maximum_requested_order": 0
  }
}
```

The reviewed adapter must establish these fields from the admitted original
input and native operations, and bind its exact source/build, completed proof,
original input and native intermediate exports by digest. The reader must
validate the known format and complete exact field values, the completed Taylor
identity, prescribed point, every order/component pair and all seven stable
numeric rows. It must reject absent or mismatched proof/artifact bindings,
unexpected format/version, candidate-derived bounds, incomplete coverage and
the presence of a fabricated `native_absolute_order` in this variant. Existing
common checks still require all three complete source-bound oracle records
before any candidate comparison.

This is a metadata admission change for a diagnostic reader, not a new numerical
reader or production serializer. Its source change and frozen rebuilt reader
need independent review after the small gate. No reader code has been changed,
and no old-format result is emitted by this protocol.

## Failure, resource and timing protocol

Use a fresh build archive and one fresh attempt directory per point. Preserve
the two old native-Series failures and every failed adapter attempt separately.
Freeze compiler, Rust source/helper, native source archives, feature identity,
all direct linked rlibs, complete linker-search inventory and executable;
preflight must identify the selected Symbolica rlib rather than only the same
source revision. The existing successful oracle build uses Symbolica rlib
SHA-256 `01601b6df1747703693fdbf78818f9bf2bb74f4e4b1a888a5971b678cc60b61a`.
A normal CLI's different feature identity is not interchangeable evidence.

The prospective default ceiling is the existing 180 seconds plus five seconds
termination grace, CPU8 and 30 GiB address space, unless the coordinator
explicitly freezes another reviewed limit. The Rust process-group timer owns
the deadline and reaps children; an address-space limit is not an RSS promise.
Serialize all Symbolica runtimes with the coordinator and Pathfinder. A passed
small gate does not itself authorize an actual point process.

Write `complete: false` progress before every potentially expensive phase and
flush completed phase timings after it. Distinguish source-hash validation,
native import, exact point binding, native factor collection, exact monomial
scaling, exact operation admission, native reversal, atom exports, native
evaluator construction, vectorization, each precision evaluation, coefficient
exports and final postflight. State whether each timing is exclusive or
cumulative; do not count native input hashing or export as evaluator time.
Record real wall time, child user/system time and peak RSS independently through
the timer. No timing from a bounded diagnostic is matched performance evidence.

Errors retain the current phase, point, dependency/source/input identities,
typed admission/evaluation error when available, completed timings and timer
outcome. If native code panics or the timer terminates it, preserve stderr and
partial progress without manufacturing a scientific result. Only set
`complete: true` and write a final result after seven ordered components,
precision/realness checks, exports and source postflight pass. No failure is a
zero result and no later point or comparison reader starts automatically after
a failure.

The next accepted milestone requires the shared-helper small-control outcome
review, the additive reader coverage change, source review, frozen
build/preflight and a coordinator runtime handoff. Actual coefficient
agreement, the remaining points, whole-graph integration and performance all
remain unverified.
