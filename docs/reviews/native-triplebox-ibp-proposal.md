# Existing native IBP: bounded on-shell comparison protocol

This protocol follows the original Taylor full-graph trial from frozen commit
`6332676`. It does not change the production default or implement new algebra.
The exact terminal outcome must be recorded before any subsequent process.

The public library already exposes
`GenerationOptions { subtraction: SubtractionStrategy::IntegrateByParts, .. }`.
The current CLI has no corresponding subtraction switch and constructs the
default Taylor options. An ignored library probe can therefore select the
existing strategy without adding a production CLI option or changing the card.
The shipped reference triple-box preset selects IBP-to-log; its coefficient-first
assembler remains a separate difference, recorded in
`native-series-fullgraph-attribution.md`.

## Ordered stages and identities

1. After the original child is reaped, freeze and review a targeted capture using
   the already archived test binary. Select the actual slow terminal
   representative, retaining its zero-based index, source chart, multiplicity,
   parameter order, original mapped terms/powers/prefactors, subtraction
   expression, template, and images. The existing hook skips earlier Laurent
   calls and returns `Cancelled`; it cannot produce a usable partial integral.
   The separate limit is 180 seconds/30 GiB of virtual address space. Retain any
   failure and do not extend the limit.
2. Release the Symbolica slot for the coordinator's pending context/workspace
   gate. During that gate, prepare a separate ignored probe around the existing
   production subtraction and Laurent/program functions. Only the strategy
   differs: reuse the captured native mapped terms and original symbols, order
   zero, unchanged limits, Gamma prefactor and measure. Export the exact powers,
   native subtraction piece counts/cancellation tuples, template/root/image
   sizes, and phase timings for each strategy. Do not expand whole bodies to
   manufacture identical representations. Freeze and independently review the
   source before a new 180-second/30-GiB representative attempt.
3. If the IBP representative completes, validate its entire Laurent vector
   against native point-first series of its own exact IBP subtraction expression
   at prescribed rational coordinates, then test the production fresh/decoded
   weighted kernels at identical rounded binary64 coordinates. Preserve all
   orders and native remainder bounds. This checks the IBP series/evaluator
   boundary; it is not a pointwise comparison against the Taylor integrand.
4. A whole-original-graph IBP trial is a separately reviewed immutable attempt,
   retaining the original graph/card, ten parameters, all 2,112 certified maps
   and 1,026 representatives, original multiplicities and all output orders.
   Bind the same canonical parametric input as the capture and preserve exact
   normalization. Use the existing native graph loader rather than another
   parser. Predeclare generation/inspection/integration limits before launch;
   no automatic follow-on is implied by this proposal.

## Scientific comparison and prior experiment limits

Taylor and IBP give different pointwise functions; their complete integrals
agree through the native repeated integration-by-parts identity and retained
boundary terms. Existing public strategy tests cover independent integral
identities, negative requested orders, and multiaxis complete vectors. Their
latest workspace gate passed. Those controls are prerequisites, not a substitute
for the new topology's whole-vector evidence. A complete physical comparison
must use complete integrals with uncertainties and the same normalization, or a
separately justified analytic identity. No coefficient is discarded because it
is expected to integrate to zero.

The previous series-first experiment changed operation order and retained 384
branches in representative 38, compared with production's 241, while operating
directly on native `Series<AtomField>` coefficient bodies. It was a different
prototype and did not establish the performance of the existing production IBP
strategy on the original on-shell graph. The older double-box Taylor/IBP timing
also does not decide this topology. The proposed comparison keeps the currently
validated late native aliases, native series coverage, exact evaluator and
precision backends unchanged. No reference Python series dictionaries, manual
convolution, callback registry, or new differentiation implementation is used.

## First preparation attempt: bounded negative result

`output/diagnostics/native-ibp-prepare-1/` records the first preparation-only
attempt. It used commit `6865f2f` plus the independently reviewed `cfg(test)`
adapter and nested ignored test. The test binary compiled successfully in
10.58 seconds; its crate profile was development/test, with the existing native
Symbolica/Numerica opt-level 2 settings. This is not a controlled release
performance comparison. The exact source archives, Cargo artifact records,
copied binary, wrapper and imported capture files were frozen before execution.
The emitted native feature set includes `tracing_max_level_info` and does not
include `faster_alloc`; no allocator change was mixed into this attempt.

The fresh Taylor replay reproduced the original captured expression by exact
native Atom equality, with all 872 pieces, in 32.382394904 seconds. The same
mapped prefactor, regular factor, powers and ordered coordinates then entered
the existing production IBP subtraction. That call did not complete within the
unchanged total 180-second preparation limit. The timer reported 180.483196637
seconds, timeout true, wrapper exit 124 and child termination by SIGINT (2).
Its later process-group SIGKILL was cleanup; the reported child signal remains
2. All 52 before/after immutable SHA-256 checks passed, the timer reported its
inputs unchanged, and the child/process group was reaped.

Native `wait4` reported peak RSS 6,020,136 KiB (about 5.74 GiB), user CPU
117.156758 seconds, system CPU 61.981263 seconds, 29,751,000 minor faults and
3,078 major faults. These are the timer's documented native accounting fields,
not an attribution of all memory to one expression or evidence of host swap.
The 30-GiB limit was a virtual-address-space limit, not an RSS limit.

Only `prepared/progress.json` exists. There is no `prepared.json`, exported IBP
expression, own-IBP oracle, Laurent vector, compiled evaluator or integration
result. Consequently, neither the independent oracle nor the later program
test was launched. The result establishes exact original-input replay and a
bounded preparation failure; it does not establish IBP's eventual piece count,
expression size, scientific vector, or relative release performance. No
timeout extension, automatic retry, full-graph launch or production strategy
change followed.
